## 一次成功什么时候值得沉淀成模板？

当同类任务重复出现时，先分离稳定规则与变量，再用新样本检验模板；不要把一次成功的长 Prompt 直接当方法。

### 在固定研究简报中操作

标出任务卡中的固定验收、可变材料和适用边界，用第二类简报验证是否仍成立。

### 在「从模板到方法资产」中最容易犯的错

没有第二样本复测就固化，会把偶然有效的表达当成稳定规则。

### 「模板与上下文材料包」应留下什么证据

- **结构检查**：模板通过第二任务复测，变量、适用范围与版本记录齐全。
- **固定案例对照**：说明这次修改解决了哪一种失败，并保存进「模板与上下文材料包」。
- **需人工核验**：事实、业务适用性与高风险决定仍由人负责。

本页为主脊柱增加 **变量、材料选择、上下文预算、来源与版本**；满足以上证据后，回到作品继续推进 Workflow：把稳定路径写成状态。

## 深入理解与原有知识

## 这一讲解决什么问题

在人机协作基本功里，你已经学过如何把一次 prompt 改成 prompt template。到了工作流与方法沉淀阶段，问题不再是“会不会写模板”，而是：

```text
这个模板能不能长期复用？
别人能不能用？
失败后能不能改进？
什么时候应该升级成 workflow 或 skill？
```

一个模板如果只是一段可复制的提示词，它仍然很脆弱。真正有价值的是把模板变成方法资产：有适用场景、有输入要求、有失败记录、有验收标准，也知道什么时候不能用。

## 模板草稿和方法资产的区别

| 类型 | 特点 | 常见问题 |
|---|---|---|
| 模板草稿 | 保留一段有效 prompt，替换变量后继续用 | 不知道适用边界，失败后不知道怎么改 |
| 方法资产 | 记录场景、变量、步骤、约束、验收、案例和失败原因 | 维护成本更高，但能持续复用 |

模板草稿解决“下次不用从零写”。方法资产解决“下次能不能稳定做成”。

## 方法资产包含什么

一个可复用的方法资产至少包含八项：

| 字段 | 作用 |
|---|---|
| 任务类型 | 说明它解决哪类任务 |
| 适用场景 | 说明什么时候可以用 |
| 不适用场景 | 说明什么时候不能套用 |
| 输入变量 | 说明每次必须替换什么 |
| 处理步骤 | 说明 AI 应该按什么顺序做 |
| 输出格式 | 说明结果应该长什么样 |
| 验收标准 | 说明什么算可用 |
| 失败记录 | 说明过去哪里出过错，下次如何避免 |

这八项能把“我有一个好 prompt”变成“我有一套可复用方法”。

## 示例：会议纪要方法资产

```text
名称：
项目周会纪要方法资产

任务类型：
把会议转写或会议记录整理成项目执行纪要。

适用场景：
项目周会、复盘会、跨部门同步会。

不适用场景：
没有会议背景、没有参会角色、讨论内容涉及敏感人事或合同决策时，不能直接生成发送版。

输入变量：
{{会议背景}}
{{参会角色}}
{{会议记录}}
{{纪要接收者}}
{{重点关注事项}}

处理步骤：
1. 提取讨论主题。
2. 区分已确认结论、讨论意见和待确认问题。
3. 提取行动项候选。
4. 标注负责人、截止时间和交付物是否明确。
5. 生成正式纪要前，先列出需要人工确认的事项。

输出格式：
会议主题 / 已确认结论 / 行动项表格 / 未决问题 / 下次追踪。

验收标准：
- 不把建议写成决策。
- 不补全没有出现的负责人和截止时间。
- 每个行动项都有原文依据或待确认标记。

失败记录：
- 2026-05-20：把“可以考虑下周做”写成“下周开始执行”。已增加“只把明确确认的内容写入结论”的约束。
```

这个资产比一段 prompt 更长，但它能被复用、检查和改进。

## 什么时候升级成 workflow

模板适合结构稳定、步骤较少的任务。如果出现下面情况，就应该考虑升级成 workflow：

1. 一个 prompt 里塞进太多要求。
2. AI 经常在事实、推断、建议之间混淆。
3. 输出前必须经过多个人工确认点。
4. 中间结果需要被单独检查。
5. 失败原因不是一句提示词能修好。

例如资料研究简报通常不适合只靠一个模板完成。它更适合拆成：

```text
任务说明 -> 事实整理 -> 推断标注 -> 风险检查 -> 简报生成 -> 人工验收
```

这就是下一讲要展开的 workflow。

## 方法资产管理表

可以用一张表管理自己的方法资产：

| 名称 | 任务类型 | 适用场景 | 输入变量 | 验收标准 | 最近失败 | 下一步改进 |
|---|---|---|---|---|---|---|
| 会议纪要方法资产 | 会议整理 | 项目周会 | 背景、记录、接收者 | 不补全决策和负责人 | 把建议写成结论 | 增加人工确认步骤 |
| 长文总结方法资产 | 材料阅读 | 报告、文章 | 原文、读者、用途 | 区分事实和观点 | 丢失限制条件 | 增加核查问题 |

这张表不需要复杂工具。关键是每次使用后能留下改进线索。

## 练习

选择一个你已经写过的 prompt template，把它升级成方法资产。

至少补齐：

1. 适用场景。
2. 不适用场景。
3. 输入变量。
4. 处理步骤。
5. 输出格式。
6. 验收标准。
7. 一个可能失败的地方。
8. 下次改进方式。

## 验收标准

完成这一讲后，你应该能做到：

- 区分模板草稿和方法资产。
- 为一个模板补充适用场景、不适用场景和失败记录。
- 判断什么时候继续维护模板，什么时候升级成 workflow。
- 让别人拿到你的模板后知道如何使用、如何检查、如何改进。
