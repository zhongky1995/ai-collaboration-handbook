## Skill 与收藏 Prompt 的本质差别是什么？

Skill 是带适用边界、流程、参考、工具/资产和验证方式的能力封装，不是把 Prompt 存进文件夹。

### 在固定研究简报中操作

为一个高频任务写适用/不适用、输入、输出、验证和失败样例；缺少任何一项都先保持草稿。

### 在「整理个人 Skill 与案例库」中最容易犯的错

只有说明文本、没有适用边界、工具/资产和验证方式的 Skill，别人无法安全复用。

### 「能力资产包」应留下什么证据

- **结构检查**：能力包含适用/不适用、输入输出、验证和失败样例。
- **固定案例对照**：说明这次修改解决了哪一种失败，并保存进「能力资产包」。
- **需人工核验**：事实、业务适用性与高风险决定仍由人负责。

本页为主脊柱增加 **适用边界、handoff、registry、owner、版本与反馈回流**；满足以上证据后，回到作品继续推进 把能力迁移到新任务并用失败样本升级版本。

## 深入理解与原有知识

## 这一讲解决什么问题

学完前面的内容后，读者可能已经有了一些 prompt、模板、workflow 和案例。但如果这些东西散落在聊天记录里，很快就会丢失。

这一讲的目标是建立个人 AI 工作台：把有效经验整理成可以继续复用和迭代的资产。

## 什么是个人 Skill

这里的 skill 不先从技术定义讲起。入门阶段可以理解为：

> 一个能在特定任务中反复发挥作用的能力包。

它可能包含：

- 任务说明模板。
- 操作步骤。
- 输入材料要求。
- 输出格式。
- 常见失败。
- 验收清单。
- 示例案例。

例如“资料研究 skill”就不是一句 prompt，而是一整套方法。

## 为什么要建案例库

AI 协作能力不是靠背概念形成的，而是靠真实案例复盘形成的。

每一次有价值的 AI 协作，都应该留下四类记录：

1. 原始任务。
2. 使用的 prompt 或 workflow。
3. AI 输出和人工修改。
4. 复盘：哪里有效，哪里失败，下次怎么改。

没有案例库，经验就会停留在感觉里。

## 个人 AI 工作台结构

可以用一个普通文件夹开始。

```text
我的AI工作台/
├── 00-使用原则.md
├── 01-任务说明模板/
├── 02-场景Workflow/
├── 03-输出验收清单/
├── 04-案例复盘/
├── 05-常见失败/
└── 06-工具记录/
```

不需要一开始做得很复杂。关键是能持续更新。

## 一个资料研究 Skill 示例

```text
名称：
资料研究简报 Skill

适用场景：
为内部讨论准备研究材料，不用于最终决策报告。

输入材料：
- 访谈摘录
- 用户反馈
- 内部流程
- 已有限制

步骤：
1. 写任务说明卡
2. 整理事实表
3. 生成推断表
4. 拆业务流程
5. 生成简报
6. 人工验收

输出格式：
- 研究问题
- 核心事实
- 初步推断
- 流程介入点
- 风险
- 待补资料

常见失败：
- AI 编造外部数据
- 推断超过材料
- 直接给最终建议

验收标准：
- 事实和推断分开
- 每条推断有依据
- 至少 3 条待补资料
```

这就是一个可继续迭代的个人能力包。

## 一个可运行 Skill 还可以包含什么

当 Skill 从个人笔记进入真实运行，它可能继续增加：

- 触发条件和不适用场景。
- 按需加载的参考资料。
- 可执行脚本、工具说明和最小权限。
- 模板、素材或种子文件。
- Validator、Eval 样例和硬失败规则。
- 产物位置、版本和 handoff 说明。

并不是每个 Skill 都要一次配齐。先用最小流程跑通，再根据真实失败添加资产和验证。如果中间过程很重、会污染主上下文，可能更适合把 Skill 放进独立 SubAgent 中执行。详细选择方法见 [Skill、SubAgent 与多 Agent 分工](../09-Agent与Harness工程/05-SkillSubAgent与多Agent分工.md)。

## 复盘模板

每次完成一个 AI 任务后，用下面模板复盘。

```text
任务名称：

这次想完成什么：

使用的 prompt / workflow：

AI 做得好的地方：

AI 出错或不稳定的地方：

我做了哪些人工判断：

最终采用了什么：

下次要改进的模板：

是否值得沉淀成 workflow：
```

## 个人系统的维护节奏

建议每周做一次轻量整理：

- 删除没用的 prompt。
- 标记效果好的模板。
- 把失败案例放进“常见失败”。
- 更新验收清单。
- 选一个任务升级为 workflow。

AI 工具会变，但你的案例和判断会积累。

## 练习

建立一个自己的 AI 工作台文件夹，并至少放入：

1. 一个任务说明模板。
2. 一个 workflow。
3. 一个验收清单。
4. 一个案例复盘。
5. 一个常见失败记录。

## 验收标准

完成这一讲后，你应该能做到：

- 有固定位置保存 AI 协作资产。
- 至少沉淀一个个人 skill。
- 案例复盘里包含 AI 输出和人工判断。
- 常见失败能反向改进模板。
- 读者不再完全依赖临场发挥。
