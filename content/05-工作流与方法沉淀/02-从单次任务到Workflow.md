# 从一次有效做法到 Workflow

上一讲你看过一份资料研究演示：限定材料、提取事实、形成推断、写出建议，再由负责人确认。即使你还没有亲自做过，也可以先观察这条做法怎样被整理成流程。

下个月，同类任务又来了。换了材料、换了主题，之前踩过的问题也一起回来：来源混了、推断越界、负责人直到最后才发现方向不对。

这时需要的不是一条更长的提示词，而是把反复发生的工作整理成一条**能看见进度、能检查结果、出错后能停下来恢复的流程**。这就是 Workflow。

## Workflow 不等于步骤清单

“收集资料—分析—写报告”当然是一组步骤，但它还没有回答：

- 收集到什么程度才能进入分析；
- 分析阶段应该留下什么；
- 来源冲突时停在哪里；
- 谁在什么时点确认；
- 失败后从哪一步继续，而不是全部重来。

Workflow 的最小结构包括五样东西：

1. **状态**：任务现在处于什么条件；
2. **动作**：这一阶段要做什么；
3. **可观察产物**：别人能检查什么；
4. **进入下一步的条件**：什么时候可以继续；
5. **异常出口**：条件不满足时去哪里。

只有动作、没有状态和检查点，流程仍然很难管理。

## 用资料研究案例画一条最小流程

| 状态 | 当前要留下的产物 | 进入下一步前必须确认 |
|---|---|---|
| 已接收 | 任务卡与材料清单 | 用途、材料范围和负责人明确 |
| 已提取 | 事实表，标注材料编号 | 关键说法能回到材料 |
| 已解释 | 推断表与未知项 | 事实和推断没有混写 |
| 已起草 | 一页简报初稿 | 建议服务于原定决定 |
| 已核验 | 核验记录与修改项 | 无来源、冲突和越界说法已处理 |
| 待确认 | 可交付版本 | 负责人完成最终取舍 |
| 已完成 | 确认后的版本与记录 | 结果已在授权范围内使用 |

这张表的价值在于，团队不必等到最后一篇“看起来完整”的报告才发现问题。每个状态都有一个可观察产物，错误会更早暴露。

## 给异常留一个出口

假设提取事实时发现两份材料对同一件事说法相反。

不可靠的流程会让 AI 自己选一个看起来更合理的版本，然后继续写下去。可靠的流程会进入一个明确的异常状态：

> **来源冲突：暂停推断，记录冲突内容、材料版本和待确认负责人。**

处理方式可能是：

- 找到更新版本；
- 保留两种说法并说明差异；
- 请求负责人判断；
- 如果冲突不影响当前决定，明确记录后继续。

关键不是所有异常都自动解决，而是异常不会悄悄穿过流程。

## 把人工门放在不可逆动作之前

“生成草稿”通常可以重来，“把结论发给客户”却可能无法收回。

因此人工确认不应只写成一句“最后人工审核”，而要放在具体位置：

- 对外发送之前；
- 修改正式数据之前；
- 使用敏感材料之前；
- 形成高风险判断之前。

在资料研究流程里，“待确认”就是一个人工门。简报可以由 AI 辅助生成，但只有负责人确认后，流程才能进入“已完成”。

## 先观察真实工作，再整理理想流程

不要坐在白板前凭空设计一条完美流程。更稳妥的做法是：

1. 选择一次已经发生的真实任务；
2. 记录实际上经历了哪些步骤和返工；
3. 找出最容易出错、最值得检查的位置；
4. 只为这些位置增加状态、产物和确认条件；
5. 再用下一次任务验证流程是否真的有帮助。

Workflow 应该来自工作，而不是强迫工作迁就一张复杂流程图。

## 什么时候先不要做 Workflow

如果任务只发生一次、目标仍在频繁变化，或者结果主要依赖无法写清的专家判断，过早固化流程会制造负担。

先把一次任务做清楚，等到以下信号出现再沉淀：

- 同类任务开始重复；
- 输入和交付物大致稳定；
- 相同错误反复出现；
- 团队需要交接或协作；
- 返工点能够被明确描述。

固定路径足够时，Workflow 就够了。只有当系统需要根据中间结果自行选择下一步、调用不同工具或反复尝试时，才有必要继续判断是否需要 Agent。

### 画一条五行流程

选一个最近重复过的任务，只写五行：

> 当前状态 → 要做的动作 → 留下的产物 → 继续条件 → 失败去向

先为最容易返工的一步填写，不必一次画完整条流程。

### 自检

检查三个问题：

1. 别人能否只看产物就知道任务走到哪里；
2. 来源冲突、材料缺失或核验失败时，流程会不会仍然向前；
3. 对外发送或正式修改之前，是否有明确的人负责确认。

如果三个问题都有答案，这已经是一条可用 Workflow 的起点。
