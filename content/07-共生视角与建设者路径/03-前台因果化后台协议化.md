## 深入理解与原有知识

## 这一讲解决什么问题

未来人和 AI 的沟通，可以理解为：

前台沟通因果化，后台过程协议化。

前台是人直接表达目标、原因、约束和判断的地方。后台是 AI、工具、数据、流程、权限和验证机制运行的地方。

这句话的价值在于：它提醒我们不要只研究 prompt 的措辞，而要同时建设可复用的过程。

## 前台沟通为什么要因果化

人与 AI 沟通时，不只是下命令，更要讲清楚因果：

- 为什么要做这件事。
- 做好后要影响什么判断。
- 哪些条件会改变结论。
- 为什么这个约束重要。
- 如果失败，代价是什么。

因果讲清楚后，AI 才更容易理解优先级。

例如：

```text
请不要只总结内容。
这份总结要给项目负责人判断是否继续投入，所以请优先保留影响决策的事实、风险和不确定性。
```

这比“总结得专业一点”更有效，因为它解释了输出用途。

## 后台过程为什么要协议化

当任务重复出现时，不能每次都靠临场表达。后台需要协议：

- 输入材料格式。
- 输出结构。
- 检查步骤。
- 异常处理。
- 权限边界。
- 交接方式。
- 评分标准。

协议化以后，AI 协作才从一次对话变成可复用流程。

## 从 prompt 到协议

一个 prompt 可以逐步演化：

| 阶段 | 形态 | 解决的问题 |
|---|---|---|
| Prompt | 一次性文字指令 | 告诉 AI 这次做什么 |
| Prompt Template | 带变量模板 | 复用输入结构 |
| Workflow | 多步骤流程 | 降低复杂任务不稳定性 |
| Agent | 目标 + 工具 + 循环 | 让 AI 持有任务身份 |
| Skill | 文件夹 + 触发 + 资源 | 复用专业能力 |
| Handoff Packet | 结构化交接包 | 在 AI 之间传递上下文 |
| Event Schema | 事件协议 | 判断处理、忽略、升级 |
| Harness | 环境 + 权限 + 验证 | 让 AI 可控执行 |
| Eval | 测试与评分 | 判断资产是否有效 |

这不是术语堆叠，而是协作越来越结构化的过程。

## 例子：从一句请求到后台协议

最初请求：

```text
帮我整理会议纪要。
```

因果化后的前台沟通：

```text
这份纪要要发给项目组，用于确认下周行动。
请优先提取决策、未决问题和行动项。
不要把建议写成已经决定的事情，因为后续会影响责任分工。
```

协议化后的后台过程：

1. 输入会议转写和会议背景。
2. 提取主题、决策、分歧、行动项候选。
3. 标注待确认事项。
4. 人工确认决策和行动项。
5. 生成正式纪要。
6. 输出追踪清单。

3. 输入格式。

5. 检查点。
6. 异常处理方式。

## 验收标准

完成这一讲后，你应该能做到：

- 前台表达包含原因、目标和影响。
- 后台流程能被重复执行。
- 有明确检查点，而不是只相信 AI 输出。
- 能看出一次 prompt 如何变成协作协议。
