# 模型怎样一步步生成回答

你把一段会议记录交给 AI，要求它整理行动项。几秒后，它给出一张完整表格：任务、负责人、截止时间一应俱全。

问题是，原始记录里只明确了任务，负责人和日期根本没有定。AI 为什么能把空白补得如此自然？

答案不是“它已经查到正确答案”，也不是“它先像人一样理解会议，再决定写什么”。更准确的说法是：

> 模型根据当前能看见的文字，为下一个文本单位计算可能性；选出一个以后，把它接回上下文，再继续预测下一个。完整回答就是这样逐步形成的。

理解这个过程，不是为了学习算法细节，而是为了弄清三件直接影响使用结果的事：为什么提示和材料会改变回答，为什么同一个问题可能得到不同版本，以及为什么语言流畅不能证明事实可靠。

## 先看一条行动项怎样长出来

假设会议记录里只有一句话：

> 下周完成登录页文案修改，负责人待定。

你要求 AI：

> 请整理成行动项，只使用记录中明确的信息；没有写明的内容标为“待确认”。

最后看到的答案可能是：

```text
任务：修改登录页文案
负责人：待确认
截止时间：下周（未给出具体日期）
```

这三行不是在模型内部先写好、检查完，再一次性贴到屏幕上的。它们是从前到后逐步生成的。为了让过程容易观察，下面把许多个细小的生成步骤合并成四个“人能读懂的阶段”：

| 屏幕上已经出现的内容 | 接下来更容易生成什么 | 依据来自哪里 |
|---|---|---|
| 还没有正文 | `任务：` | 指令要求整理“行动项”，常见输出会先写任务字段 |
| `任务：` | `修改登录页文案` | 原记录明确写了要完成的事情 |
| `负责人：` | `待确认` | 原记录明确写着“负责人待定” |
| `截止时间：` | `下周（未给出具体日期）` | 原记录只支持“下周”，不支持某一天或某个时刻 |

注意：这张表是帮助理解的教学展开，不是模型内部的运行日志。真实模型按 token 生成，实际切分和每一步候选会因模型与产品设置而不同。但有一点没有变：**每一步都会结合已经出现的上下文与训练中学到的模式，决定接下来写什么。**

现在把指令换成一句看似更积极的话：

> 请整理成一张完整、专业的行动项表。

模型可能给出：

```text
任务：修改登录页文案
负责人：王敏
截止时间：下周五 18:00
```

这张表看起来更“完整”，问题却更大：原记录里既没有“王敏”，也没有“下周五 18:00”。模型在训练中学到了大量行动项表的常见写法：“负责人”后面常接姓名，“截止时间”后面常接具体日期。于是这些文字在结构上非常顺；但**结构上顺，不等于材料里有。**

把两次生成放在一起，区别就很清楚：

| 指令给模型的条件 | 生成时更容易走向 | 结果能否直接采用 |
|---|---|---|
| “完整、专业” | 尽量填满常见字段 | 不能；缺失字段可能被合理化补齐 |
| “只使用明确的信息；缺失写待确认” | 保留空缺，并说明证据边界 | 仍需核对，但更容易验收 |

这就是“上下文会改变回答”的一个具体版本：上下文不是让模型忽然知道了事实，而是在每一步生成时，改变哪些后续文字更合适。

## 再把刚才的过程还原成 token

大模型处理文字时，不一定以完整汉字或单词为单位。输入会先被拆成一串 **token**。一个 token 可能是一个词、词的一部分、一个汉字组合或标点；具体怎样拆分取决于模型使用的编码方式。

模型不会一次写出整张表。它会反复做同一种计算：在已经出现的 token 之后，哪些 token 更可能接下来出现？

可以把刚才的过程压缩成下面这条链路：

```text
输入文字
  → 拆成 token
  → 结合前文计算每个位置的上下文表示
  → 得到“下一个 token”的概率分布
  → 按生成规则选择一个 token
  → 把它接回前文，继续下一轮
  → 遇到结束条件后停止
```

因此，“补全”不是单独补一个词，也不是先在内部写好全文再显示出来。它指的是：**模型用连续的下一步预测，逐渐形成一句话、一张表或一段程序。** “下一个 token”虽然很小，连续几百次以后，就能形成一份结构完整、甚至看起来很专业的答案。

## 上下文怎样影响下一步

模型在每一步预测时，会综合当前上下文中的不同位置。Transformer 模型里的 **注意力机制**，可以让当前生成位置对前文不同 token 分配不同权重，从而形成与这段上下文有关的内部表示。

这里要避免一个常见误解：模型并不是先完成一张人类可见的表，写着“这是会议纪要任务，所以应该输出负责人”。“识别任务类型”可以用来描述最终表现，却不是一次独立、可观察的人类式判断。

更贴近实际的解释是：训练让模型学到了大量文字之间的统计关系；当前指令、材料、格式和已经生成的内容一起改变下一步的概率分布。于是不同上下文会把回答推向不同方向。

例如，同一段会议记录配上两条不同指令：

| 指令 | 更可能出现的结构 | 原因 |
|---|---|---|
| 整理行动项；缺失信息写“待确认” | 任务、负责人、时间、状态 | 指令明确规定了输出字段和缺失项处理 |
| 整理给老板看的风险摘要 | 风险、影响、优先级、建议动作 | 读者和用途改变了需要保留的信息 |

这并不说明模型找到了两个预先存好的模板。它说明上下文改变了连续预测的条件。

## 模型在训练时学到什么，现在又在做什么

还要区分两个容易混在一起的阶段。

### 训练阶段

模型在大量数据上调整内部参数，学习语言、代码、知识表达和任务示例中反复出现的模式。后续的指令微调和偏好对齐，会进一步影响它怎样响应请求、遵守格式或回避某些内容。

这些学习结果被压进模型参数，但它们不是一座可以逐条检索、逐条出示出处的文档库。模型能生成一条看似熟悉的事实，不代表它此刻已经打开并核对了那条事实的原始来源。

### 当前生成阶段

你这次提供的系统规则、任务说明、材料、对话历史和示例，构成模型本轮能直接利用的上下文。它们不会因为一次对话就重新训练模型参数，而是在这次生成中改变候选 token 的概率。

所以，给出一个合格示例，通常能让本轮输出更接近示例；指出“负责人缺失时写待确认”，也能约束后续版本。但这不等于模型已经永久学会，换一个新对话或删掉这些要求，表现可能再次变化。

## 为什么同一个问题会出现不同答案

模型每一步得到的不是唯一答案，而是一组候选 token 及其概率。产品还会使用一套 **解码规则** 决定怎样从中选择，例如更偏向最高概率，或保留一定随机性和多样性。

因此，两次回答可能不同，原因至少有三类：

- 上下文不同：任务、材料、对话历史或系统规则发生了变化；
- 产品设置不同：模型版本、解码参数、可用工具或安全规则不同；
- 生成具有随机性：即使输入相同，也可能走向不同的后续表达。

“再问一次得到同样答案”只能说明两次生成相近，不能构成独立证据；“换个模型问一下”也不自动等于事实核查。

## 为什么会出现流畅但没有依据的内容

下一 token 预测优化的是：在当前条件下，什么延续更符合模型学到的模式和产品规则。它不会自动把“每一句都能被外部证据支持”作为唯一目标。

前面的行动项已经展示了这个过程。如果你只要求“整理成完整行动项表”，完整表格的常见模式里通常包含负责人和日期。“完整”会给模型一种填满字段的方向，但材料没有提供这些事实，于是生成可能滑向一个合理姓名或日期。它补的是**语言和结构上的空白**，不是已经核实的事实。

更可靠的任务说明是：

> 只提取记录中明确出现的信息。负责人、日期或结论没有明确时写“待确认”，不要根据上下文猜测。输出后逐项标注原文依据。

这条要求不能保证模型永不出错，但它把未知项的处理方式说清了，也让结果更容易验收。

可以把三个维度分开看：

| 维度 | 要问的问题 | 不能由什么代替 |
|---|---|---|
| 流畅性 | 文字是否通顺、结构是否完整？ | 不能代替事实支持 |
| 相关性 | 是否回应了当前任务和读者？ | 不能代替业务适用性 |
| 可证实性 | 关键主张能否回到材料或独立来源？ | 不能由自信语气证明 |

## 模型、检索和产品不是一回事

日常使用的 AI 产品可能不只包含一个生成模型。产品还可能在生成前后接入网页搜索、知识库检索、数据库、计算工具、权限规则和事实引用。

```text
用户问题
  → 产品选择或检索材料
  → 模型基于问题与材料生成候选
  → 产品显示来源、执行工具或进行安全检查
```

因此，当一个 AI 回答附带网页来源时，不能笼统地说“模型自己上网知道了”。更准确的说法是：产品先取得了一些材料，再让模型基于这些材料组织回答。

这仍然需要检查两件事：系统找来的材料是否相关，生成出的主张是否真的被这些材料支持。想进一步理解系统怎样找到“意思接近”的段落，可以按需阅读 [Embedding 与语义检索](04-Embedding与语义检索.md)。

## 把机制转成三个使用动作

知道生成机制后，最有用的不是背术语，而是改变输入与检查方式。

1. **把决定输出方向的条件写进上下文。** 说明用途、读者、可用材料、输出形态和不能猜的内容。
2. **把未知项规定成一种合法输出。** 允许模型写“材料未提供”“存在冲突”“需要核查”，不要用“必须完整”逼它填满空白。
3. **把关键主张拉回证据。** 数字、时间、归因、承诺和外部事实，要定位到给定材料或独立来源后才能采用。

这一讲和上一讲正好接起来：AI 能很快形成候选，是因为它能连续生成；候选不能直接成为答案，是因为“很可能接下来这样写”和“现实中确实如此”是两种不同判断。

### 做一次“依据与补全”检查

准备一段包含明确任务、但没有负责人和截止时间的短会议记录，然后让 AI 整理行动项。

先使用普通指令，再补充下面的边界后生成第二版：

> 只使用记录中明确出现的信息；负责人和截止时间缺失时写“待确认”；每条行动项附一小段原文依据。

比较两版并标出：

1. 哪些字段来自原文；
2. 哪些字段是模型自行补出的；
3. 第二版是否仍有无法回到原文的内容；
4. 哪一条要求真正改变了结果的证据状态。

### 教学反馈

如果第一版出现了姓名或日期，不能只写“AI 幻觉了”。请指出它为什么容易发生：任务要求完整结构，但材料没有给字段，也没有规定未知项怎样表示。

如果第二版仍有编造，说明任务说明只能降低风险，不能替代验收。最终应回到会议记录逐项核对，而不是让模型再回答一次来证明自己。
