# 入门术语地图：遇到哪个词，就查哪一段

## 30 秒判断

- **遇到陌生词时**：查它负责哪一步、不能代替什么，再回到正文。
- **只想完成眼前任务时**：先查任务与材料；不必预先背完整词表。
- **术语口径**：本页采用本课程的教学定义；Agent、Skill、Harness 等词在不同产品里可能有不同用法。

## 一条工作链，先找到词的位置

```text
用 Prompt 说清任务
  → 选择 Context（当前材料）
  → 模型生成候选；必要时通过检索取得资料
  → Tool 执行读取、计算或写入
  → Workflow / Agent 组织多步工作
  → Harness 支撑运行与控制
  → 人验收本次结果；Eval 检查方法能否复用
  → 保存为 Template / Skill，留好版本与案例
```

这是一张职责地图，不是每个任务都必须经历的步骤。改写一段邮件，可能只需要任务说明、材料和人工核对。

## 任务与材料：先查这五个词

### Prompt · 任务输入

你给模型的请求及相关输入。日常也常把整段输入叫 Prompt；做任务时最好分清“要做什么”和“依据什么”。不是一句能让所有任务都正确的咒语。见[六格任务卡](../02-人机协作基本功/01-把模糊问题变成AI能执行的任务.md)。

### Context · 当前上下文

本轮真正进入模型的信息，可能包括规则、任务、材料、对话和工具结果。上传过、聊过，不代表这次一定都看得见。人为整理的“上下文包”只是其中一部分。见[上下文包](../02-人机协作基本功/02-上下文包是什么.md)。

### Token · 模型处理的单位

文字被拆成的编码单位，可能是词、词的一部分、汉字组合或标点；不等于一个字。通常用于计算输入输出长度和相关用量。见[模型怎样生成回答](03-模型如何生成回答.md)。

### 上下文窗口 · 本轮容量范围

模型一次处理输入与生成内容的容量限制。容量大，不等于所有细节都会被正确使用；长材料仍要选择、分段和核对。见[上下文工程与长任务](../09-Agent与Harness工程/03-上下文工程与长任务.md)。

### 模型与产品 · 生成能力和使用环境

模型提供生成、理解等能力；产品还可能加入搜索、附件解析、记忆、工具和权限。某个产品能上网，不代表生成模型的参数里存着实时网页。见[模型、检索和产品的区别](03-模型如何生成回答.md)。

## 查资料：相关不等于正确

### Embedding · 可比较的数字表示

把文字等对象表示成一组数字，用来比较关系。意思相近的反馈可能靠近，但条件、版本和处理方式仍可能不同。见[Embedding 与语义检索](04-Embedding与语义检索.md)。

### RAG · 检索增强生成

先从外部资料取回相关内容，再把它交给模型生成回答。它可以使用语义检索，也可以使用关键词等方法；不是只要用了 Embedding 就已完成 RAG。需要分别检查取回的材料和生成的结论。见[检索与生成的链路](04-Embedding与语义检索.md)。

## 从回答到行动：这些词职责不同

### Template · 模板

为重复任务保留固定字段和可替换内容。例如每周纪要都包含决定、行动项和未决问题。模板稳定输出结构，不负责自动获取材料或授权发送。见[方法资产的区别](../05-工作流与方法沉淀/04-整理个人Skill与案例库.md)。

### Workflow · 工作流程

预先定义步骤、分支、检查点和异常出口。它也能调用工具、重复执行和等待确认；这些能力本身不等于 Agent。见[从一次做法到 Workflow](../05-工作流与方法沉淀/02-从单次任务到Workflow.md)。

### Tool / 工具调用 · 实际执行动作

Tool 是搜索、读文件、写文件、计算等具体能力；工具调用是模型提出动作与参数后，由外部程序执行。聊天里写“已保存”不能代替实际文件。见[工具地图](../06-工具地图与个人系统/01-按任务类型理解AI工具.md)。

### Agent / Agent Loop · 动态选择与循环

在本课中，Agent 围绕目标，根据状态和实际反馈选择下一步；Agent Loop 是观察、选择、执行、写回并决定是否继续的循环。多步、定时或用了工具，都不是单独充分的判断条件。见[什么时候需要 Agent](../05-工作流与方法沉淀/03-什么时候需要Agent.md)。

### Harness · 运行支撑

组织模型调用、工具结果回传、上下文和状态，并按配置管理权限、检查、停止和恢复。它不是更强的模型，也不是统一的必装软件；具体范围因项目而异。见[从 Prompt 到 Harness](../09-Agent与Harness工程/01-从Prompt到Harness工程.md)。

### Skill · 可复用能力说明

把一类任务的适用条件、输入、方法、输出、验收和失败处理保存下来，必要时带参考、工具和脚本。它可以由人按说明执行，也可以被支持的 Agent 加载；不等于收藏一条长提示词。见[整理 Skill 与案例库](../05-工作流与方法沉淀/04-整理个人Skill与案例库.md)。

### SubAgent / Handoff · 独立执行与交接

SubAgent 是被委托处理子任务的执行单元；Handoff 是传递目标、状态、证据、产物和下一步，部分模式还移交控制权。多一个角色名不自动带来独立验证。见[Skill、SubAgent 与多 Agent 分工](../09-Agent与Harness工程/05-SkillSubAgent与多Agent分工.md)。

## 检查与恢复：遇到工程词再查这里

| 词 | 日常理解 | 不能误认为 |
|---|---|---|
| Eval · 评估 | 用预先约定的样例和标准检查一套方法 | 给一次回答打感觉分就能证明稳定 |
| Trace · 运行记录 | 记录可见工具动作、结果、状态、版本和检查 | 必须取得模型隐藏思维链 |
| Guardrail · 护栏 | 在输入、动作或结果处设置边界与检查 | 写一句“请小心”就已强制限制权限 |
| Schema · 字段约定 | 规定输入输出的字段、类型和可选值 | 格式正确就证明事实和权限正确 |
| 幂等 | 重复同一请求不会额外产生相同副作用 | 重试多少次都安全 |
| Fail closed · 不确定时停止 | 权限或执行状态不明时，暂停高影响动作 | 所有小问题都让任务崩溃 |
| Registry · 资产登记表 | 记录能力名称、入口、版本、负责人与边界 | 文件夹存在就已经可以安全复用 |

检查结果看[轻量 Eval](../04-判断验证与风险/04-如何设计轻量Eval.md)；运行记录看[可观测性](../09-Agent与Harness工程/07-Eval可观测性与持续改进.md)；权限与恢复看[工具权限](../09-Agent与Harness工程/04-工具权限与安全边界.md)；资产登记看[AgentOS 能力资产](../09-Agent与Harness工程/06-从真实工作到AgentOS能力资产.md)。

## 用一个任务检查是否分清了职责

“每周整理纪要”不必直接叫 Agent：固定字段是 Template；先提取、后核对、再等待批准是 Workflow；根据实际缺口选择补读哪份资料才体现动态选择。按说明复用方法可以是 Skill；组织工具与状态是 Harness；换成缺失、冲突材料检查方法则是 Eval。

遇到新词时，能回答“它解决哪一步的问题、不能代替什么”，通常比记住英文全称更有用。

## 可选：用三句话检查职责

1. “每份纪要都用同样的字段。”主要是在复用什么？
2. “来源冲突时，根据新信息决定补读哪一份。”体现什么选择？
3. “换几份缺失和混乱材料，检查模板是否仍合格。”在做什么？

对照：第一句是 Template；第二句体现本课所说的 Agent 动态选择，但还需要权限和停止控制；第三句是 Eval。不要只凭“每周”“多步”或“用了工具”就把任务叫 Agent。
