# 六阶段作品与升级标准

<!-- PRACTICE:START -->
> **作品库 · 进度真相源** · 正式能力进度只由六阶段作品和 required 条件决定，阅读篇数、术语练习与场景练习都不会自动授予里程碑。

## 先看结论：正式作品只有六份

你会在同一个真实任务上依次留下六份可检查证据：**Prompt 任务卡 → Context 材料包 → Workflow → Agent 运行卡 → 最小 Harness → Skill / AgentOS 能力资产包**。前一份作品暴露的失败，决定后一阶段要增加什么控制；不能跳过未通过的升级门。

| 阶段 | 正式作品 ID | 作品名称 | 通过后证明什么 | 升级关系 |
|---|---|---|---|---|
| Prompt | `artifact-task-card-v1` | Prompt 任务卡 | 任务可执行、可验收，人类责任清楚 | 才能为一个明确判断选择 Context |
| Context | `artifact-context-template-v1` | Context 材料包 | 材料有选择、有来源、有版本、有预算 | 才能把稳定路径写成 Workflow |
| Workflow | `artifact-workflow-v1` | Workflow | 状态、检查点、人工门和异常可见 | 路径依赖环境反馈时再升级 Agent |
| Agent Loop | `artifact-agent-loop-v1` | Agent 运行卡 | 每轮行动改变状态，能停止、等待和恢复 | 才能识别需要哪些运行控制 |
| Harness | `artifact-minimum-harness-v1` | 最小 Harness | 权限、Trace、Eval、异常和预算共同受控 | 通过后才能封装成可交接能力 |
| Skill / AgentOS | `artifact-capability-package-v1` | Skill / AgentOS 能力资产包 | 别人能找到、接手、验证、升级这项能力 | 进入第二个真实任务验证迁移 |

## 所有作品共用的证据合同

每次检查都必须留下以下字段。缺少字段时只能标为 `draft` 或 `needs_revision`，不能因为“文件已经保存”就判通过。

| 字段 | 要回答的问题 |
|---|---|
| `task / case` | 这份作品来自哪个真实任务，给谁使用？ |
| `stage / artifactId` | 它属于六阶段中的哪一层，唯一 ID 是什么？ |
| `status` | `draft`、`needs_revision` 还是 `passed`？ |
| `version` | 当前是哪一版？上一版为什么要改？ |
| `criteria` | 每个 required 条件满足还是未满足，证据在哪里？ |
| `feedback` | 这是结构检查、固定案例对照，还是需人工核验？ |
| `pending` | 具体要改哪个字段、规则、权限或 Eval？ |
| `nextUse` | 下一阶段如何使用它，或下一次真实任务复用在哪里？ |

反馈分三类：

- **结构检查**：系统可以确定字段是否存在、数量是否足够、状态是否完整。
- **固定案例对照**：系统只能判断本课程给定场景中的选择是否符合预设边界。
- **需人工核验**：事实真伪、组织权限、业务判断、高风险决定和最终发布必须由人负责。

## S1 · Prompt 任务卡

### Required 条件

1. 说明结果给谁使用、支持什么行动或决定。
2. 列出本轮允许使用的输入材料，而不是让 AI 自行补资料。
3. 规定输出形态、篇幅或结构。
4. 至少写三条可观察的验收条件。
5. 明确不能编造、不能越权或不能代替人的边界。
6. 指定事实、风险或最终发布的责任人。

### 通过证据与反馈

证据字段至少包括 `goalAudience`、`goalUse`、`materials`、`outputShape`、`acceptanceCriteria` 和 `humanResponsibility`。结构齐全后仍需人工判断：任务是否真实、风险是否可接受、验收标准是否真的服务于使用者。

常见待修改项是“研究一下”“写得专业”等不可验收表达。把它改成“给团队负责人一页简报，用于决定是否试行；包含三条结论，每条标注材料来源”。

**升级门**：六项 required 都有证据，状态为 `passed`，Context 才能继承明确的目标与验收。

## S2 · Context 材料包

### Required 条件

1. 材料总量没有超过本轮预算。
2. 每份材料有来源、日期或版本。
3. 没有混用已经被替代的新旧版本。
4. 至少包含一份直接支持当前决定的高信号材料。
5. 为被排除的过期、重复、低信号或无关材料记录理由。

### 通过证据与反馈

证据字段包括 `selectedMaterials`、`exclusionReasons`、`budget`、来源与版本清单。系统可以检查预算和版本冲突；材料是否可信、是否遗漏关键利益相关方，只能由人核验。

**升级门**：材料选择可以解释，旧版与未知来源没有悄悄进入当前上下文，Workflow 才能把处理顺序固定下来。

## S3 · Workflow

### Required 条件

1. 开始条件与完成条件明确。
2. 每个状态都有可观察的中间产物。
3. 不可逆动作之前存在人工门。
4. 来源冲突、材料不足或核查失败有独立异常状态和恢复动作。

### 通过证据与反馈

证据字段包括 `states`、`hasBoundaries`、`gate`、`exception`、`observable outputs`。一张只写“先分析、再生成、最后检查”的步骤表不算通过，因为失败后仍不知道停在哪里。

**升级门**：稳定路径可以恢复；只有下一步确实依赖工具结果或环境反馈时，才增加 Agent Loop，而不是为了显得高级。

## S4 · Agent 运行卡

### Required 条件

1. 记录本轮观察到的状态，而不是重复原始目标。
2. 说明为什么选择这一步行动和工具。
3. 工具结果会写回状态，下一轮能看到变化。
4. 有成功、等待人工、失败关闭或重试上限。
5. 保存可接续的恢复点与简短 Trace。

### 通过证据与反馈

证据字段包括 `observation`、`action`、`outcome`、`trace`、`retryLimit` 和 `recoveryPoint`。固定案例能检查“信息不足时请求人工”是否优于“继续猜”；真实环境中的工具可靠性与停止条件仍要由人复核。

**升级门**：至少一条运行轨迹能解释为什么继续或停止，之后再为真实失败面设计最小 Harness。

## S5 · 最小 Harness

### Required 条件

1. 工具动作按对象和风险分为 `allow / ask / deny`。
2. 外部查询、可逆写入和不可逆发布有不同权限。
3. Trace 能回看关键输入、状态、动作、结果和停止原因。
4. Eval 同时检查结果质量与运行轨迹。
5. 材料缺失、来源冲突、工具失败或越权有关闭与恢复路径。
6. 轮次、时间或成本有上限；人类升级点明确。

### 通过证据与反馈

证据至少包括权限矩阵、三类运行轨迹、Eval 评分与依据、异常处理、预算和责任人。结果看起来正确但轨迹越权，整体仍是 `needs_revision`。

**升级门**：标准、等待人工、失败关闭三种情况都能解释和恢复，才可以封装能力资产。

## S6 · Skill / AgentOS 能力资产包

### Required 条件

1. 写清适用与不适用边界。
2. 有维护 Owner 和可识别版本。
3. Handoff 能让下一位执行者独立接续。
4. 保存 Eval 基线、已知失败与反馈回流方式。
5. 区分可共享方法与个人、客户或组织私有信息。
6. 标明 registry 位置和下一次真实任务的复用入口。

### 通过证据与反馈

证据字段包括 `applicability`、`owner`、`version`、`handoff`、`evalBaseline`、共享边界和 `nextUse`。AgentOS 在这里表示管理能力资产的教学视角，不是行业统一产品定义。

**完成门**：能力资产包通过后，换一个真实任务做迁移。迁移失败不是退步，而是给下一版补边界、Eval 或 Handoff 的证据。

## 版本与状态怎样推进

```text
v1 draft
  → 规则检查
v1 needs_revision
  → 按具体待修改项修复
v1 passed
  → 在第二个任务中发现新失败
v2 draft（保留 v1 证据）
```

`passed` 只代表当前任务、当前证据和当前规则版本通过。修改已通过作品时创建新版本，不覆盖旧版；否则你无法解释能力为什么变化，也无法回归旧样例。

## 旧练习怎样保留，但不竞争主线

以下知识仍有价值，但只能成为六份正式作品的前置判断、辅助检查、迁移练习或附加证据：

- **AI 任务判断**：放在 Prompt 前，帮助识别 AI 可参与部分、人类责任和风险等级。
- **术语地图**：作为 Reference 自测，用来解释概念影响哪一步，不计里程碑。
- **真实场景产出记录**：作为六阶段作品的案例附件，保存 AI 初稿、人工修改和最终结果。
- **事实核查与发布检查**：进入 Harness 的 Eval 和人工门，不再单独构成另一套结课作品。
- **AIGC brief、候选比较与版权检查**：作为具体任务的附加证据，仍按六阶段升级。
- **学习复盘**：进入能力资产包的版本说明与迁移复盘，不单独改变进度。
