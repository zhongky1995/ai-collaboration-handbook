# 六阶段可复制作品模板

<!-- PRACTICE:START -->
> **作品库 · 可操作模板** · 只复制你当前阶段的一份模板。每份作品都必须带 required 结果、反馈、待修改项、版本和下一次复用，文件存在不等于能力通过。

## 怎样使用这页

先选一个真实任务，完成 **Prompt 任务卡**；通过后让下一份模板继承它，不要在每个阶段重新抄目标。六份正式模板依次是：**Prompt 任务卡、Context 材料包、Workflow、Agent 运行卡、最小 Harness、Skill / AgentOS 能力资产包**。
<!-- PRACTICE:END -->

## 每份作品都先复制这段元数据

```yaml
artifactId:
taskOrCase:
stage:
status: draft # draft | needs_revision | passed
version: v1
courseRuleVersion: v3
requiredResults: []
feedbackRecords: []
pending: []
previousVersion:
nextUse:
owner:
updatedAt:
```

一次反馈建议这样记录：

```yaml
- criterionId:
  result: met # met | unmet | human_check
  evidence:
  feedbackType: 结构检查 # 结构检查 | 固定案例对照 | 需人工核验
  why:
  fix:
  checkedAt:
```

```text
- 材料 / 来源 / 日期或版本 / 用途：

不得使用或不得自行补全的信息：
-

输出形态：
- 篇幅：
- 结构：
- 交付形式：

可观察的验收条件：
1.
2.
3.

AI 可以参与：
人必须负责：
主要风险与升级方式：

required 结果：
- [ ] 使用者与用途明确
- [ ] 输入材料可得且范围明确
- [ ] 输出形态可执行
- [ ] 至少三条验收条件可逐项判断
- [ ] 不做范围或风险边界明确
- [ ] 人类责任明确

最近反馈：
待修改项：
下一次复用：Context 材料选择
```

任务适合性判断保留在这里作为前置证据：把任务拆成事实查找、材料整理、候选生成、业务判断和不可逆行动，说明 AI 可参与哪部分、哪部分必须由人负责。它帮助你写好任务卡，但不形成额外里程碑。

```text
|---|---|---|---|---|---|
|  |  |  |  |  |  |

排除材料：
| 名称 | 排除理由 | 何时需要重新考虑 |
|---|---|---|
|  |  |  |

冲突与未知：
- 新旧版本冲突：
- 待核查说法：
- 缺失材料及负责人：

required 结果：
- [ ] 总量在预算内
- [ ] 来源和版本可见
- [ ] 未混用被替代版本
- [ ] 有直接支持当前决定的高信号材料
```

材料越多不代表上下文越好。事实核查从这里开始：不知道来源和版本的说法要标为“待核查”，不能悄悄进入结论。

```text
- [ ] 观察与当前状态明确
```

```text
|---|---|---|---|---|---|

| 样例 | 预期结果 | 预期轨迹 | 硬失败 | 实际证据 | 结论 |
|---|---|---|---|---|---|
| 标准输入 |  |  |  |  |  |
| 关键缺失 |  |  |  |  |  |
| 来源冲突 / 权限诱导 |  |  |  |  |  |

- [ ] 不可逆动作保留人工门
```

事实核查、发布检查和高风险升级都在本阶段成为 Eval、硬失败或人工门。结果正确不能抵消越权轨迹。

```text

能力名称：

适用场景：
不适用场景：
Owner：
Registry 位置：

资产清单：
- Prompt 任务卡：
- Context 材料包：
- Workflow：
- Agent 运行卡：
- 最小 Harness：
- Eval 基线与样例：

Handoff：
- 接手人先读什么：
- 当前状态和未决问题：
- 最小权限：
- 下一动作：
- 失败时联系谁：

版本说明：
- 相比上一版修改了什么：
- 哪个失败促成修改：
- 回归了哪些旧样例：

共享边界：
- 可以公开或团队共享：
- 只保留抽象、不公开实现：
- 客户 / 个人 / 组织私有：

required 结果：
- [ ] 适用与不适用边界明确
- [ ] Owner、版本和 Registry 明确
- [ ] Handoff 足以独立接续
- [ ] Eval 基线与失败回流可见
- [ ] 私有与共享边界清楚
- [ ] 写明下一次真实任务复用位置

最近反馈：
待修改项：无 / 具体列出
下一次复用：第二个真实任务与迁移复盘
```

AgentOS 在这里是整理、登记、交接和迭代能力资产的视角。真正的完成证据不是“我整理了文件夹”，而是另一位执行者能按 Handoff 接续，并用旧 Eval 解释新版本是否退化。

## 提交前只做这四项检查

1. 六份作品的 `artifactId`、阶段、版本和上游引用能否一一对应。
2. 每个 required 条件是否有证据，而不是只打勾。
3. 每个未满足条件是否有反馈类型、原因、修改动作和负责人。
4. `passed` 作品被修改时是否创建新版本并保留旧证据。

评分和升级门见 [六阶段作品与升级标准](01-阶段作业与评分标准.md)；不知道失败应回到哪一层时，使用 [案例索引与证据复盘](03-案例索引与复盘卡.md)。
