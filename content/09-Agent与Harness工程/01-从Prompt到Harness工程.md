# 进入 Agent 之前：从 Prompt 到 Harness

这一篇是进阶课入口。

如果你还没有稳定完成过“定义任务—准备材料—核验输出—整理 Workflow”，可以先停在核心课。Agent 不会自动修复一个目标模糊、材料混乱或无人负责的流程；它只会让这条流程运行得更快、更频繁。

当任务会反复发生、需要调用工具，并且下一步要根据中间结果变化时，才值得继续。

## 先看一个会不断重复的任务

假设团队每周都要整理一份竞品更新简报。

一次性完成它并不难：给 AI 几份网页和公告，让它提取变化、比较差异、起草摘要，再由人核验。

真正进入持续运行后，新的问题出现了：

- 某个网页打不开，要重试、换来源，还是停止？
- 两个来源说法冲突，应该采用哪一个？
- 系统能读取哪些目录，能不能访问外部网站？
- 简报可以自动保存，但能不能自动发送？
- 中途失败后，是从头再来，还是从已经核验的材料继续？
- 如果结果有问题，谁能查到它使用过什么材料、采取过什么动作？

这些问题已经不是一句 Prompt 能回答的。它们关心的是系统怎样运行。

## 五个层次分别解决什么

| 层次 | 主要解决的问题 | 什么时候够用 |
|---|---|---|
| Prompt | 这一次怎样生成一个候选 | 单轮、低风险、有人立即检查 |
| 模板 | 同类请求怎样复用相同字段 | 输入输出稳定，但仍由人逐次发起 |
| Workflow | 多步任务怎样按固定路径推进 | 步骤明确，异常主要由人处理 |
| Agent | 中间结果不同时，系统怎样在边界内选择下一步 | 需要动态选择工具、来源或重试方式 |
| Harness | Agent 怎样在受控环境中持续运行 | 需要权限、状态、记录、验证和恢复 |

层次越高，不代表方案越先进，只代表系统承担的责任更多。能用模板解决，就没有必要建 Agent；能用固定 Workflow 解决，就不必引入动态决策。

## Agent 和 Harness 不是一回事

可以把 **Agent** 理解为“根据当前状态选择下一步的执行者”。

而 **Harness** 是包在它外面的运行环境。它负责让 Agent 知道自己能做什么、做到哪里必须停、发生问题后怎样追查和恢复。

一个最小 Harness 通常要回答：

- **状态**：任务现在进行到哪里；
- **工具**：可以调用什么，输入输出格式是什么；
- **权限**：哪些动作允许、拒绝或需要人工确认；
- **检查**：怎样判断当前结果可以继续；
- **记录**：使用了哪些材料，执行了哪些动作；
- **恢复**：超时、冲突或失败后从哪里重新开始。

模型负责生成和选择，Harness 负责约束运行。模型更强，并不会自动带来权限更清楚、记录更完整或失败更容易恢复。

## 回到每周竞品简报

如果材料每周都由人整理好，系统只按固定顺序提取、比较、起草和等待确认，一条 Workflow 可能已经足够。

只有出现下面这类动态选择，Agent 才开始有价值：

- 来源不可用时，在授权列表里选择备用来源；
- 发现版本冲突时，进入核查分支；
- 信息不足时，决定补充检索还是标记未知；
- 检查未通过时，只重做有问题的部分。

即使引入 Agent，也不意味着它可以自行发布。Harness 仍应限制：

- 只能读取授权材料；
- 外部检索和敏感数据按规则处理；
- 重试次数有上限；
- 每次来源选择和修改都有记录；
- 对外发送前必须由负责人确认。

这才是“能运行”与“可以放心运行”之间的差别。

## 进入进阶层前，先过三个判断

### 1. 任务已经稳定吗

输入、输出和验收方式仍在频繁变化时，先继续打磨任务和 Workflow。否则系统会把变化中的试验误当成固定规则。

### 2. 动态选择真的必要吗

如果所有任务都走同一条路径，Workflow 更简单、更容易检查。不要为了使用 Agent 而制造分支。

### 3. 运行责任有人承担吗

至少要有人决定工具权限、敏感数据边界、人工确认点和故障处理方式。没有负责人，就不应让系统扩大行动范围。

三个判断都比较清楚，才适合继续学习：系统怎样根据当前情况选择下一步，怎样调用工具，怎样限制权限，以及怎样记录、检查和恢复运行过程。后续各讲会分别解释这些概念。

## 这一层不承诺什么

进阶工程课不会提供一个“全自动员工”的万能配方。它关注的是更朴素的问题：

> 当 AI 不再只生成一段文字，而是开始读取状态、调用工具并采取动作时，怎样让过程仍然可见、可控、可停止、可恢复。

这也是 Harness 存在的原因。

### 画一张最小运行护栏草图

选一个你想自动化的真实任务，只写六行：

1. **任务**：系统反复完成什么；
2. **动态选择**：哪个中间结果会让下一步改变；
3. **工具**：完成动作需要调用什么；
4. **权限**：哪些动作允许、拒绝或必须先询问；
5. **检查与恢复**：怎样知道可以继续，失败后从哪里重来；
6. **人工门**：谁在对外发送、正式修改或高风险判断前确认。

### 自检

如果“动态选择”没有具体答案，先停在 Workflow。

如果权限、恢复或人工门没有负责人，这张草图只能用于讨论，不能直接扩大系统行动范围。
