## 深入理解与原有知识

## 这一讲解决什么问题

很多 AIGC 输出不好，不是模型不会画，而是人的视觉需求没有说清楚。

文字任务需要任务说明卡。视觉任务也一样，只是它要多说明：画面主体、风格、构图、颜色、使用场景和不能出现的内容。

视觉 brief 的作用，就是把一句“帮我生成一张图”，改写成 AI 能执行、人能检查的生成说明。

你可以把它理解成：视觉 brief 先让人把目的、受众、场景和验收说清楚；prompt 再把这些内容转成 AI 可以执行的生成协议。好的 prompt 往往来自好的 brief，而不是凭空写出来的。

## 视觉 brief 包含什么

一个可用的视觉 brief 通常包括九个字段。

| 字段 | 要回答的问题 |
|---|---|
| 使用场景 | 这张图用在哪里 |
| 表达目标 | 这张图要帮助读者理解什么 |
| 目标读者 | 谁会看这张图 |
| 主体 | 画面里最重要的对象是什么 |
| 场景 | 背景或环境是什么 |
| 风格 | 照片、插画、3D、信息图还是草图 |
| 构图 | 横版、竖版、近景、远景、留白、视角 |
| 约束 | 不要出现什么，哪些元素必须保留 |
| 验收标准 | 什么算可用，什么必须返工 |

这些字段不是为了让 prompt 变长，而是为了让视觉结果服务任务。

## brief、prompt 和参考素材有什么区别

| 名称 | 给谁看 | 作用 | 常见错误 |
|---|---|---|---|
| 视觉 brief | 人和 AI 都能看 | 说明用途、目标、边界和验收方式 | 只写审美，不写用途 |
| 生成 prompt | 给 AI 执行，也给人复盘 | 把 brief 转成可执行生成协议 | 只堆形容词，不写画面细节 |
| 参考素材 | 给 AI 提供示范 | 固定构图、风格、色彩、主体或镜头 | 上传后不说明参考什么 |

一个专业一点的 AIGC 流程，通常不是“想到一句 prompt 就生成”，而是：

```text
业务需求
  ↓
视觉 brief
  ↓
生成 prompt
  ↓
候选图
  ↓
反馈和迭代
  ↓
发布前验收
```

## 视觉语言怎么写得更具体

如果你不熟悉设计术语，可以先用下面这张表。

| 你想表达 | 可以使用的词 |
|---|---|
| 构图 | 16:9 横版、4:5 竖版、居中主体、左侧留白、从左到右流程、俯视桌面 |
| 镜头距离 | 远景、中景、近景、特写、俯拍、平视 |
| 光线 | 柔和自然光、低对比、明亮、侧光、暖色室内光 |
| 风格 | 现代 editorial illustration、半扁平插画、轻 3D、真实摄影、线性图标 |
| 颜色 | 白色和浅灰背景、绿色强调色、低饱和、暖黄色点缀、品牌色参考 |
| 材质 | 纸张、玻璃、金属、磨砂、柔和阴影、干净桌面 |
| 情绪 | 专业、克制、亲和、安静、可信、学习感、工作感 |
| 避免项 | 不要可读文字、不要 logo、不要水印、不要机器人、不要夸张科幻光效 |

这些词不是越多越好。你只需要选出和当前任务最相关的 5-8 个。

## 从模糊需求到视觉 brief

### 原始需求

```text
生成一张 AI 课程配图。
```

这个需求缺少使用场景、读者、表达目标和风格边界。

### 改写后的视觉 brief

```text
使用场景：
AI 入门知识库文章配图。

表达目标：
让读者理解 AIGC 不是随便出图，而是从视觉 brief 到生成候选，再到人工验收和最终使用的协作流程。

目标读者：
业务同事，熟悉内容和汇报工作，但不一定懂图像生成技术。

主体：
一个人在电脑前整理视觉需求，屏幕和画面中出现多个候选图、人工勾选和最终素材。

场景：
干净的办公桌和知识工作环境。

风格：
清爽、专业、半扁平插画，适合课程文章。

构图：
16:9 横版，从左到右呈现 brief、生成候选、人工验收、最终资产。

约束：
不要出现可读文字、品牌 logo、科幻机器人、夸张发光大脑或水印。

验收标准：
画面能看出流程；风格适合课程；没有文字乱码；没有明显版权或品牌风险。
```

这段 brief 已经能变成图像生成 prompt。

## 从 brief 到 prompt 的三步

### 第一步：保留用途和主体

先说这张图用来做什么，以及画面里最重要的对象是什么。

```text
为一篇 AI 入门知识库文章生成 16:9 横版配图。画面主体是一个业务同事在电脑前整理视觉需求，旁边有任务卡、候选图缩略图和人工勾选动作。
```

### 第二步：补充风格、构图和颜色

```text
使用清爽、专业的半扁平 editorial illustration 风格。画面从左到右呈现 brief、候选图、人工验收和最终素材。白色和浅灰背景，绿色作为强调色。
```

### 第三步：写清限制和验收

```text
不要出现可读文字、品牌 logo、真实软件界面、科幻机器人或夸张发光大脑。画面要能看出 AIGC 是一个从需求到候选再到验收的协作流程。
```

组合起来就是一段可执行 prompt。

## 图像 prompt 的基本结构

可以用这个模板：

```text
用途：

主要画面：

场景和主体：

风格：

构图：

色彩和氛围：

必须包含：

必须避免：

验收标准：
```

如果生成工具支持英文 prompt，也可以把 brief 翻译成英文再生成。不是因为英文一定更高级，而是很多图像生成模型在英文视觉描述上更稳定。

## 什么时候需要参考图

当你很难用语言说清楚风格、构图或材质时，参考图比形容词更有效。

但参考图要写清角色。

弱写法：

```text
参考这几张图，帮我生成一张 AI 学习活动图。
```

更好的写法：

```text
图 1 只参考构图：左侧留出标题空间，右侧放主体画面。
图 2 只参考色彩：白色、浅灰和绿色强调色。
图 3 只参考图标风格：简洁线性，不复制具体图案。

请生成一张适合公司群发布的 AI 学习活动图，不要复制参考图里的文字、logo 或人物身份。
```

如果你不说明参考图的作用，AI 可能同时借用主体、颜色、构图和细节，结果反而更难控制。

## 为什么要写“避免项”

AIGC 很容易沿用常见视觉套路。比如一提到 AI，就容易出现：

- 机器人。
- 发光大脑。
- 蓝紫色科幻背景。
- 复杂线路板。
- 漂浮的数据流。

这些元素不是不能用，但如果你的课程想表达“工作协作能力”，它们反而会把读者带偏。

所以视觉 brief 里要明确避免项。

但避免项也不要过长。写太多“不要”，模型可能仍然抓住其中一些词。更好的方式是先写你要什么，再补充最重要的禁用项。

弱写法：

```text
不要机器人，不要蓝色，不要科技感，不要复杂，不要未来，不要像海报，不要太商业。
```

更好的写法：

```text
画面要像真实办公学习场景：干净桌面、电脑、任务卡、候选图缩略图和人工勾选动作。整体清爽、克制、适合知识库文章。避免机器人、发光大脑、品牌 logo 和可读文字。
```

## 练习

把下面模糊需求改成视觉 brief：

```text
帮我做一张适合发在公司群里的 AI 学习活动图。
```

至少写出：

1. 使用场景。
2. 表达目标。
3. 目标读者。
4. 主体。
5. 风格。
6. 构图。
7. 约束。
8. 验收标准。

## 验收标准

完成这一讲后，你应该能做到：

- 区分文字 prompt 和视觉 brief。
- 把模糊视觉需求拆成可执行字段。
- 写出清楚的风格、构图和避免项。
- 用验收标准判断生成图是否服务任务。
