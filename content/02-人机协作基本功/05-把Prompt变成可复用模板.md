## 哪些内容应该固定，哪些必须留成变量？

模板只固定稳定规则，把任务对象、时间、材料和输出变量显式留空；没有适用/不适用边界的模板会把旧经验误用到新任务。

### 在固定研究简报中操作

从当前任务卡提取至少两个变量，用第二个任务复测；需要整段重写的部分还不是稳定模板。

### 在「把 Prompt 变成可复用模板」中最容易犯的错

把具体日期、人物和材料固化，会在下次复用时悄悄带入旧任务。

### 「模板与上下文材料包」应留下什么证据

- **结构检查**：至少两个变量能替换，且用第二个任务验证适用边界。
- **固定案例对照**：说明这次修改解决了哪一种失败，并保存进「模板与上下文材料包」。
- **需人工核验**：事实、业务适用性与高风险决定仍由人负责。

## 深入理解与原有知识

## 这一讲解决什么问题

很多人用 AI 有一个共同问题：这次问得不错，下次又从零开始。

如果每次都重新写 prompt，你很难积累方法。真正能带来长期收益的，是把一次有效协作整理成可复用模板。

模板不是固定话术，而是把任务中稳定的结构保留下来，把会变化的部分变成变量。

## Prompt 和 Prompt Template 的区别

Prompt 是一次性输入。

Prompt Template 是可复用输入结构。

例如，一次性 prompt：

```text
请帮我把这篇文章总结成 5 条要点，给产品团队看。
```

模板：

```text
请把下面材料总结给 {{目标读者}}。

使用目的：
{{使用目的}}

输出结构：
1. 一句话结论
2. 关键事实
3. 对目标读者的意义
4. 需要核查的问题

约束：
- 不补充材料外信息。
- 推断必须标记。
- 输出控制在 {{字数}} 字以内。
```

模板的价值在于：下次只需要替换变量，不需要重新想结构。

## 什么内容适合模板化

适合模板化的任务通常有三个特点：

- 高频出现。
- 输出结构相对稳定。
- 有明确验收标准。

例如：

- 会议纪要。
- 长文总结。
- 资料研究。
- 工作邮件。
- PPT 页面任务表。
- 发布前检查。

不适合过早模板化的任务：

- 你还没做过几次。
- 每次差异很大。
- 你还不知道什么算好。
- 风险很高但没有检查机制。

## 模板的基本结构

一个可用模板通常包含：

| 部分 | 作用 |
|---|---|
| 任务说明 | 固定任务类型 |
| 变量 | 每次需要替换的信息 |
| 输入材料 | 放置材料的位置 |
| 输出格式 | 固定结构 |
| 约束边界 | 固定风险控制 |
| 验收标准 | 判断是否可用 |
| 迭代提示 | 不合格时如何修改 |

## 从一次 prompt 到模板

### 第一步：找出稳定部分

例如会议纪要任务中，稳定部分是：

- 提取会议结论。
- 提取行动项。
- 标注未决问题。
- 列出下次追踪。

### 第二步：找出变量

变量可能是：

- 会议类型。
- 项目背景。
- 参会角色。
- 转写材料。
- 接收者。
- 发送语气。

### 第三步：固定输出格式

例如：

```text
输出格式：
1. 会议主题
2. 已确认结论
3. 行动项表格
4. 未决问题
5. 下次追踪
```

### 第四步：加入验收标准

```text
验收标准：
- 不把建议写成决策。
- 行动项必须包含负责人；没有负责人则标记待确认。
- 截止时间没有明确出现时，不要补具体日期。
```

## 模板示例：会议纪要

```text
请把下面会议内容整理成 {{纪要类型}}。

会议背景：
{{会议背景}}

接收者：
{{接收者}}

重点关注：
{{重点关注内容}}

输入材料：
{{会议转写或记录}}

输出格式：
1. 会议主题
2. 已确认结论
3. 行动项表格：任务 / 负责人 / 截止时间 / 交付物 / 待确认
4. 未决问题
5. 下次追踪

约束边界：
- 不记录闲聊。
- 不把建议写成已确认决策。
- 负责人或截止时间不明确时，标记“待确认”。

验收标准：
- 接收者能根据纪要推进下一步。
- 每个行动项都能被追踪。
- 所有不确定内容都有标记。
```

## 模板维护

模板第一次写出来不一定完美。每次使用后，记录三件事：

1. 哪个变量经常忘记填。
2. 哪个约束经常不够清楚。
3. 哪个验收标准最能提升质量。

模板是活的，不是一次写完就不动。

## 练习

选择一个你本周会重复出现的任务，把一次 prompt 改成模板。

要求：

- 至少包含 4 个变量。
- 有明确输出格式。
- 有 3 条约束边界。
- 有 3 条验收标准。

## 验收标准

完成这一讲后，你应该能做到：

- 区分一次性 prompt 和 prompt template。
- 把高频任务中的稳定结构和变量拆开。
- 写出一个别人也能复用的模板。
- 知道模板需要通过使用持续维护。
