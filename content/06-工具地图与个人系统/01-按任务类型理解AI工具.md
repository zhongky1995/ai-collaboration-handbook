# 按任务类型理解 AI 工具

## 30 秒判断

- **要解决的问题**：不是“哪个 AI 最强”，而是当前任务需要生成、检索、制作还是执行；
- **适合何时打开**：你在几个工具之间犹豫，或习惯用同一个聊天工具完成所有工作；
- **先记住的边界**：产品功能、价格和数据政策会变化，真正采用前要核对当前版本与组织规则。

## 先判断任务，再选择工具

工具选择最容易让人分心。看到新工具就试，最后会得到很多账号、很多收藏夹，却没有稳定产出。

本课程的原则是：先判断任务，再选择工具。工具不是学习主线，任务才是。

你要先问：

- 我要完成的是理解、生成、检索、制作、执行，还是管理？
- 这件事对准确性、格式、速度、隐私有什么要求？
- 工具失败时，我是否有人工兜底办法？

## 六类任务

### 1. 对话与思考

适合：

- 澄清问题。
- 生成思路。
- 拆解任务。
- 进行多轮迭代。

关键能力不是“回答”，而是能跟你一起把模糊意图变清楚。

### 2. 检索与研究

适合：

- 找公开资料。
- 汇总来源。
- 比较多个观点。
- 追踪最新信息。

这类任务必须重视来源、时间和可核查性。

### 3. 写作与改写

适合：

- 起草邮件、通知、方案。
- 调整语气。
- 改结构。
- 生成不同读者版本。

重点是沟通目标，而不是文采。

### 4. 文档与 PPT 制作

适合：

- 生成文档结构。
- 设计页面任务。
- 整理汇报逻辑。
- 转成可展示材料。

重点是信息架构和表达任务。

### 5. 图像、音视频和多模态

适合：

- 生成视觉草图。
- 分析图片。
- 处理视频脚本。
- 辅助内容创作。

这类任务要额外注意版权、肖像、品牌和可发布边界。

### 6. 自动化与 agent

适合：

- 重复流程。
- 多步骤任务。
- 调用外部工具。
- 执行和检查结合的流程。

这类任务必须设置权限、日志和验收标准。

## 选择工具的判断表

| 任务问题 | 更适合的工具类型 | 核心检查 |
|---|---|---|
| 我需要想清楚问题 | 对话工具 | 是否能多轮追问 |
| 我需要最新资料 | 搜索/研究工具 | 是否给出来源和时间 |
| 我需要写给别人 | 写作工具 | 是否能按受众改写 |
| 我需要做汇报 | 文档/PPT 工具 | 是否能控制结构 |
| 我需要处理图片视频 | 多模态工具 | 是否符合发布边界 |
| 我需要重复执行 | 自动化/agent 工具 | 是否可监控和回滚 |

## 换一个工具，仍然能沿用的操作

很多 AI 工具都允许你提供材料、说明目标、查看结果、继续修改和保存作品。界面名称可以不同：新任务可能叫“新对话”或“项目”，材料入口可能叫“附件”或“添加文件”。先按动作找入口，再根据当前工具实际支持的能力操作。

下面以“把会议记录整理成纪要”为例。描述的结果是可能出现的情况，不是所有产品都会返回相同界面或答案。

**1. 新建任务，明确这次做什么。** 在新任务或对话中写明“整理这次会议记录”。你可能看到空白输入区，也可能需要选择工作文件夹。确认当前使用的是这次会议的材料，避免混入另一项目。

**2. 放入材料，核对是否读到。** 粘贴逐字稿；支持附件时，也可选中文件上传。你可能看到附件名、解析提示或直接收到回答。文件名只能说明文件被选中；请它指出材料中的会议主题和一段原话，再对照检查是否读到了内容。

**3. 说明交付要求，查看第一版。** 写明读者、用途、输出结构和缺失信息的处理方式。你可能得到结构化初稿，也可能收到追问。能回答的条件就补充；未知负责人和日期保留待确认。

**4. 指出具体问题，检查修改。** 说明需要修改的段落和依据。工具可能直接修改原文，也可能新增一个版本。对比该段是否改对，并抽查其他内容有没有被意外改动。

**5. 保存作品，打开确认。** 要求交付可保存的纪要。返回聊天文字时，复制到常用文档工具保存；返回附件时，下载并打开；写入工作目录时，找到具体文件并核对内容。云端目录中的文件还需要导出到电脑。

同一句“帮我生成纪要”，在一个工具里可能返回正文，在另一个工具里可能生成文件，在具备执行能力的 Agent 应用里还可能包含读取材料、写文件和检查结果的多步过程。**共同的任务方法可以复用，执行能力和交付位置仍要核对。**

## 认识基本 Agent 应用

Agent 应用通常把模型、工具和运行循环组合起来，让系统根据当前结果继续选择动作。它们也可能提供普通问答或计划模式，所以不能仅凭产品名称判断这次任务是否真的执行了。

可以先认识三种常见使用方式；这是按任务划分的教学分类，产品之间可能重叠。

### 研究与资料型

你给出问题、检索范围和输出要求，系统可能搜索网页、读取来源、比较材料，再生成带出处的报告。你需要查看具体来源、日期和引用是否支持结论；“搜索过”不表示每条结论都得到证实。

### 文件与编程型

Codex、Claude Code 是这类工作的代表。你选择项目或工作目录，说明要制作或修改的文件，它们可以在所支持的环境中读写文件、执行命令并检查结果。你可能看到文件变更、运行记录、预览入口或成品文件。第一步先确认工作位置，再从一个小文件任务开始。

[Claude Code 官方概览](https://code.claude.com/docs/en/overview)说明了代码读取、文件编辑和命令执行等能力；[Codex 官方仓库](https://github.com/openai/codex)提供相应产品与使用资料。具体入口、权限和可用功能随产品版本与运行环境变化。

### 通用执行型

以 Manus 为例，它提供带网络和文件系统的任务环境，可围绕目标组织多步工作。你可以提交资料整理或作品制作任务，再查看进展与交付文件。运行在云端的文件不一定出现在你电脑的文件夹中，需要通过产品提供的下载或导出入口取回。[Manus 官方介绍](https://manus.im/docs/introduction/welcome)

选择时先看你希望得到的是一段回答、一份文件，还是一组已经执行并检查过的动作。无需为了入门同时使用这几类产品。

## Agent 调用的“工具”是什么

日常说的“AI 工具”可能指整个应用；Agent 里的 tool 通常指一次具体可执行的能力。模型提出要做什么及其参数，外部程序执行动作，再把结果交回后续步骤。常见能力包括：

**搜索：按关键词寻找来源。** 返回的可能是标题、链接、摘要，也可能没有结果。找到链接之后，还需要打开材料核对。

**读取：取得指定文件或网页的内容。** 可能返回原文、部分内容或读取失败。看到文件名与读到全文是不同状态。

**写入或编辑：实际保存或修改内容。** 比如把纪要保存为指定文件，或更新其中一段。可能返回保存位置、变更记录或写入错误。模型在聊天中写“已保存”仍需文件证据支持。

**运行代码或命令：让程序执行处理。** 比如统计表格、转换文件或检查网页，可能返回数值、日志、生成文件或报错。需要让工具实际运行，不能把代码文本当作执行结果。

**浏览器操作：改变或读取页面状态。** 比如打开页面、填写表单和下载附件。可能看到新页面、下载记录，也可能没有变化。操作后需检查是否发生预期变化。

**外部服务连接：调用其他系统中的能力。** 比如查询日历、读取资料库和创建任务。可能返回记录、编号或权限不足提示。有连接入口不等于当前账号有相应数据和动作权限。

这是一张能力地图，不是所有 Agent 的默认功能清单。实际能调用什么，要看当前提供的工具、账号权限和运行环境。

## 看懂它现在进行到哪一步

假设你说：“读取这次会议记录，生成纪要并保存。”以下是教学示意，并非真实运行日志：

```text
用户：给出目标与会议记录的位置。
模型：提出读取这份记录。
读取工具：返回原文，或返回找不到文件。
模型：根据原文整理；如果读不到，则查找允许范围内的文件或说明缺失。
写入工具：保存纪要，返回文件位置。
检查步骤：重新打开文件，对照原文核查决定与行动项。
用户：查看纪要及待确认项，决定是否采用。
```

你可以据此分清“提出了计划”“调用了工具”“拿到了结果”“验证了作品”。工具返回错误时，补充正确文件或处理具体原因；只有计划时，继续明确是否要执行；文件已生成时，进入验收。

组织这些调用、回传结果和保存进展的运行支撑，属于 **Harness** 的职责。它让多步工作有机会连续推进；具体解释见[进入 Agent 之前：从 Prompt 到 Harness](../09-Agent与Harness工程/01-从Prompt到Harness工程.md)。

## 一个任务为什么可能需要多种工具

假设你要准备一份给客户看的产品更新说明：

| 工作阶段 | 更适合的能力 | 这一阶段的完成证据 |
|---|---|---|
| 澄清读者与沟通目标 | 对话与思考 | 能写清客户读完后应该知道或确认什么 |
| 核对当前功能与发布日期 | 检索、官方文档或内部记录 | 每条事实有当前来源和版本 |
| 起草客户版本 | 写作与改写 | 表达适合关系场景，没有超出材料的承诺 |
| 排成可发送文档 | 文档制作 | 标题、层级、表格和附件可正常使用 |
| 发送前检查 | 人工核验或受控 Workflow | 事实、收件人、附件与授权全部确认 |

“一个任务只选一个工具”并不是目标。更重要的是每种工具只承担它擅长且能被检查的动作，最终交付仍沿着同一条证据链推进。

## 验收标准

完成这一讲后，你应该能做到：

- 不再用同一个工具解决所有问题。
- 能说明每类工具适合什么、不适合什么。
- 工具选择服务任务，而不是服务好奇心。
